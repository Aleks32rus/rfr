Ты — ревьюер тестового кода `rfr-e2e`. Применяй skill `rfr-test-review` из `.agents/skills/rfr-test-review/SKILL.md` и отвечай в его формате. Соблюдай инструкции проекта.

## Ограничения

- Не правь файлы и не применяй патчи к рабочей копии.
- Из Bash разрешены только `git diff`, `git log`, `git show`, `git apply --check` и `./gradlew :rfr-e2e:test --tests …`. Не используй другие команды, перенаправления или составные команды для изменения рабочей копии.
- `git apply --check` используй только для проверки применимости патча, без его применения.
- Владение `Page` и `BrowserContext` остаётся за `@UsePlaywright`.

## Порядок работы

1. Прочитай skill `rfr-test-review`, diff и затронутые файлы целиком. Сверяй пути и имена с кодом: текущий каталог расширения — `junit/`, тест — `test/UserExtensionTest.java`.
2. Для каждого ресурса найди владельца и три момента: получение ресурса, регистрацию и место хранения под управлением владельца, освобождение. Пройди всю цепочку декораторов, начиная с `UserRequest.fixture()`, включая ресурсы дополнительных пользователей и предусловий. Проверь успешное выполнение, частичную подготовку и ошибки.
3. Для каждого замечания укажи файл, строку, сценарий сбоя и способ воспроизведения: существующий тест или конкретный падающий шаг `create()`. Отделяй подтверждённые факты от предположений.
4. Если вывод подтверждается существующим тестом без изменения кода, запусти `UserExtensionTest`: `./gradlew :rfr-e2e:test --tests io.student.rangiffler.test.UserExtensionTest`. Соблюдай правила проекта о разрешении запуска тестов. Не меняй код ради воспроизведения; невозможность запуска укажи в ограничениях.
5. Раздели ответ на три списка: «подтверждено запуском», «по чтению кода», «не проверено». Для каждого ресурса укажи владельца, получение, хранение и освобождение. Если дефектов нет, явно скажи об этом и перечисли ограничения решения.
