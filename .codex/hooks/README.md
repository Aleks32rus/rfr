# Компиляция после изменения исходников

Проектный `.codex/hooks.json` добавляет синхронные хуки Codex для `Bash`
(включая `exec_command`) и `apply_patch`. Пользовательский хук RTK сохраняется.

`PreToolUse` запоминает SHA-256 исходников, `PostToolUse` сравнивает содержимое.
Поэтому уже существующие незакоммиченные изменения не вызывают сборку после
каждой команды чтения, а повторное изменение того же файла обнаруживается.
Снимки разделены по репозиторию, сессии и вызову инструмента и хранятся
в системном временном каталоге `rfr-codex-compile`, вне Git.

- Java: изменения `.java` в `src` модулей `rfr-api`, `rfr-auth`, `rfr-e2e`
  запускают `compileJava` и `compileTestJava` затронутых модулей одним вызовом Gradle.
- Фронтенд: изменения исходников, конфигурации JSON/JS/TS, стилей и ресурсов
  в `rfr-gql-client` запускают `npm run build` (TypeScript и Vite).
- Каталоги `build`, `node_modules`, `dist`, `.git`, `.idea` не отслеживаются.
- Тесты не запускаются. Изменения Java-схем и файлов Gradle отдельно не отслеживаются.
- Команды ограничены четырьмя минутами каждая; общий таймаут хука — десять минут.

Вывод stdout/stderr, ошибка запуска и код завершения возвращаются агенту через
`hookSpecificOutput.additionalContext`. Ошибка компиляции не отменяет сделанное
изменение. Codex сохраняет слишком длинный вывод отдельно и передаёт агенту
сокращённый вывод с путём к полному файлу.

Для активации открой проект заново и доверь оба хука через `/hooks` в CLI
или Settings → Hooks в приложении Codex. Автоматически менять записи доверия
не требуется. Нужны Node.js, JDK 25, установленные зависимости фронтенда
и доступные зависимости Gradle.

Хуки отслеживают изменения инструментами агента. Они не являются наблюдателем
за файловой системой для правок в IDE между вызовами инструментов.
