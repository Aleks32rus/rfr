# rfr-e2e

- Для Page Object применяй `.agents/skills/rfr-page-objects/SKILL.md`. Скилл не разрешает отступать от глобальных правил: при добавлении или изменении `public static String URL`, публичных методов без интерфейса либо превышении лимита атрибутов согласуй противоречие до реализации.
- Не копируй нарушения глобальных правил из существующих тестов. Не включай параллельный запуск в рамках несвязанной задачи.
- Используй `@UsePlaywright` и параметр `Page`; не создавай второй механизм управления браузером. Локаторы, действия и UI-проверки размещай в PO и компонентах.
- Для подготовленного пользователя используй `@User TestUser`, для регистрации через UI — `UserFixture` в `try-with-resources`. Не дублируй очистку fixture в тестах или lifecycle-методах.
- Очистка касается только данных пользователя теста; после ошибки очистки API всё равно пробуй очистить auth, сохраняя дополнительные ошибки как suppressed.
- Схему БД не меняй из тестов. SQL и подключения не размещай в PO и сценариях.
- Заполнение и отправку формы разделяй. Действия и проверки не смешивай; не добавляй `checkPageLoaded` и аналоги.
- Для UI используй автоматические проверки Playwright, а не Hamcrest над мгновенно прочитанным состоянием; глобальные ограничения числа и положения утверждений сохраняются.
- При зависимости следующего шага от сохранения используй `page.waitForResponse(..., save::click)` с проверкой GraphQL `operationName`. Затем проверяй сохранённые данные независимым чтением или перезагрузкой.
- Не устраняй неоднозначность локатора через `first()`: уточняй область и доступное имя. Варианты MUI Select могут быть в портале вне формы; страну выбирай по вложенному флагу с точным именем.
- Проверяй локаторы через Playwright MCP на работающем приложении, когда инструмент доступен; иначе укажи отсутствие браузерной проверки. Ручной сценарий через MCP не является запуском автотестов и не требует согласования их запуска.
- Действия и проверки PO отмечай `@Step` на русском, параметры фиксируй в Allure; секреты маскируй и не включай в названия шагов. Маскирование не удаляет секреты из исходных результатов Allure — проверяй их перед публикацией.
- Не обходи отсутствующую серверную функциональность в тестах: подготовь описание проблемы и согласуй дальнейшую работу.
